- `history_length=4` 总计四槽，记录当前样本后为当前及此前三帧；最新帧在最后。
- `concatenate_terms` 控制组内字段连接，`flatten_history_dim` 控制历史轴压平。

- Q24 选择框架初始化：局部 reset 清空指定环境，首次 append 后首帧填满四槽；不追加环境历史有效长度协议。

## 已核查的频率机制：事实与决定分别记录

| 概念 | 本地源码中的机制 | 本需求中的结论 |
| --- | --- | --- |
| 物理步长 | `sim.dt` | 已确认先保留 0.005 s |
| 环境步长 | `step_dt = sim.dt * decimation` | 必须为 0.02 s；这一乘积不唯一决定两个因子 |
| 当前 Go2 继承值 | `sim.dt=0.005`、`decimation=4` | 已确认作为新增任务初始基线，满足 50 Hz |
| 策略动作生成 | 标准 runner 每个采样步执行一次 `alg.act`，随后一次 `env.step` | 50 Hz 对应逐环境步交互；不表示每秒进行 50 次梯度更新 |
| RSSM 隐状态更新 | 当前标准 rsl_rl 路径没有现成的 RSSM 独立频率配置 | 需要扩展时序契约；不得杜撰已有配置字段 |
| 传感器刷新 | `sensor.update_period` 控制传感器缓存的到期刷新 | 不会自动调用 RSSM；深度图 10 Hz 已由用户单独确认 |
| rollout / 优化 | `num_steps_per_env` 控制采样长度，epochs/mini-batches 控制优化 | 不得用这些参数冒充控制频率 |

证据：Isaac Lab `source/isaaclab/isaaclab/envs/manager_based_env.py:261-275`、`source/isaaclab_tasks/isaaclab_tasks/core/velocity/velocity_env_cfg.py:352-366`、`source/isaaclab/isaaclab/sensors/sensor_base.py:204-224`；实际安装包 `rsl_rl/runners/on_policy_runner.py:79-108`。官方对照：[OnPolicyRunner v5.5.1](https://github.com/leggedrobotics/rsl_rl/blob/v5.5.1/rsl_rl/runners/on_policy_runner.py)。

### R04-002 — 50 Hz 策略交互时间基准

- **Requirement ID**：R04-002。
- **初始条件**：环境已初始化，时钟以仿真时间计算。
- **输入/触发条件**：连续执行策略动作及对应的环境步进。
- **可观察行为**：每个环境步推进 0.02 s；一次动作对应一个策略步，物理子步不作为额外策略步。
- **验收标准**：初始基线采用 `sim.dt=0.005 s`、`decimation=4`，乘积为 `0.02 s`；连续 N 个策略步对应 N 次动作交互和 `N * 0.02 s` 仿真推进；按步编号核对，不依赖墙钟速度或浮点时间累加来判断节拍。
- **尚不明确的问题**：本阶段没有墙钟实时性、延迟或抖动阈值；如后续需要改变物理/动作基线，须说明需求与验证依据。

### R04-003 — 10 Hz 世界模型时序接口

- **Requirement ID**：R04-003。
- **初始条件**：50 Hz 环境交互成立，已取得本 episode 的初始化数据；算法依据逐环境仿真步进、reset 和帧信息维护时序。
- **输入/触发条件**：持续进行环境交互，经过连续的 5 个策略步。
- **可观察行为**：世界模型隐状态的周期更新间隔为 0.1 s；中间策略步使用最近的隐状态。环境提供原始数据、准确的仿真时间、reset 及深度帧信息；更新边界、实际 RSSM 调用和 `h_t` 由后续 rsl_rl 算法负责。
- **验收标准**：环境提供足以核对时序和帧来源的可信信息；初始化数据位于该环境 reset 后、首次动作前，算法周期位于该环境完成第 5、10、15…步后；初始化与周期分开计数，每周期包含 5 个策略步；传感器按自身配置刷新，环境不将世界模型周期扩展为跨观测组同步配对约束。本阶段以记录输入和调用的替身验证接口契约，不能据此宣称真实 RSSM 调度器已实现或集成通过；不把 rollout 边界当成 episode reset，也不直接假设可被随机化的 `episode_length_buf` 与相机相位一致。
- **尚不明确的问题**：时间与帧信息的字段及传递方式；初始化输入中尚无已执行动作时的表示。非更新步状态保持、RSSM 内部初始化数值及真实调度器验证属于后续算法集成。

### R04-004 — 世界模型的已执行动作窗口

- **Requirement ID**：R04-004。
- **初始条件**：同一环境实例已完成至少 5 个策略动作，未发生 episode reset。
- **输入/触发条件**：在策略时刻 n 取得世界模型输入。
- **可观察行为**：rsl_rl 将环境观测和实际动作数据组织为 RSSM 的 `a[n-5:n]`，共五个已执行动作，从早到晚排列；样本是 wrapper 裁剪后、关节目标转换前的环境输入。环境 G1 提供四槽历史，不能只把其中四个 last_action 当作五个动作。
- **验收标准**：用不同的已知动作逐步核对，最终模型输入窗口内容、顺序、尺度和环境实例均匹配；不包含待生成动作、不重复物理子步、不混入其他环境或上个 episode 的动作；本阶段根据最终职责边界验证环境数据可支持该构造，不宣称后续算法已实现。
- **尚不明确的问题**：终止步实际动作的可靠通路；rsl_rl 跨调用组织五动作窗口的具体协议；不足五个动作时的表示、初始化和布局。Q16 旧填充方案仍未批准。

### R04-010 — Table III 基础奖励的 Go2 移植

- **Requirement ID**：R04-010。
- **初始条件**：奖励所需的状态、接触和动作历史可用；Go2 适配参数已确认。
- **输入/触发条件**：每个环境步计算基础奖励。
- **可观察行为**：包含论文 Table III 的 16 项基础奖励，公式和权重有可追溯依据；每个策略步的聚合值为 `0.02 * sum(weight * term)`；AMP 留到后续。
- **验收标准**：每个原始奖励项及其权重可独立核对，再独立核对带 `0.02 s` 时间积分的聚合值；接触对象、站立条件、历史动作和高度参考系与确认契约一致。高度项采用 `z_ref=mean(z_i)`，其中 `z_i` 来自以基座为中心、随偏航旋转的局部采样窗口内有效且可通行的地形表面，排除地形定义为沟壑内部的样本，`h=z_base-z_ref`；用包含台阶高低面、沟壑底、无效和越界样本的已知几何分别核对纳入集合及均值。奖励每 0.02 s 根据当步地形计算，不使用旧策略步的缓存；全无有效样本时本步高度奖励项为零并记录原因；四足均腾空时该项为零。reset 后第一个真实动作的一阶/二阶动作差项均为零，第二个动作可计算一阶差而二阶仍为零，第三个起两者均按公式计算；局部 reset 清空对应真实动作历史且不影响其他环境，不使用 G1 填充样本计算差分。不按已有函数名称推定公式等价。
- **尚不明确的问题**：Go2 目标高度、站立速度和接触判据、需要的阈值；地形采样窗口尺寸、点距、射线量程、可通行表面标记与有效命中的具体接口，以及腾空接触检测阈值仍待确认；不得把论文 Apollo 的目标高度直接当作 Go2 决定。

### R04-011 — 地形难度课程与 episode 结果统计

- **Requirement ID**：R04-011。

- **输入/触发条件**：发生已定义的课程评估事件，并输入对应的 episode 结果或统计数据。
- **可观察行为**：基座进入 tile 终点且至少一足在终点支撑面建立接触、无任务失败时记成功并结束 episode；任务失败包括基座非法接触、跌落、离开允许运动区域，分别记录原因；正常腿部/足部过障接触不自动判失败。分类优先级为任务失败 > 完成目标 > 仅超时，最后允许步完成仍可成功。按地形类型和难度分别统计完整 episode，成功为成功样本，任务失败和未成功超时为失败样本，手动 reset 或初始化中断不计入成败。地形难度按确认规则调整，可观察当前等级、评估输入及调整结果；不启用速度课程，不随课程评估扩大速度命令范围，G4 命令继续按自身配置生成。

### Q27 高度参考面（已确认定义，边界仍待细化）

Q27a 选择基座周围地形采样高度的均值作为高度参考：`z_ref=mean(z_i)`、`h=z_base-z_ref`；高度误差以 `h-h_target` 表示。Go2 的 `h_target` 数值仍 TBD。开源候选调查见 [HEIGHT_REFERENCE_RESEARCH.md](HEIGHT_REFERENCE_RESEARCH.md)；此决定依据用户选择，不表示上游跑酷项目实际启用了相同奖励。

Q30–Q33 进一步确定：局部窗口以基座为中心、随偏航旋转；均值仅纳入有效、可通行的地形表面，地形生成器标记的沟壑内部即使射线命中也排除。无有效样本时高度奖励项为零并记录该原因；四足均无接触时高度奖励项为零。两个零值条件分别可验证，不推定 Go2 目标高度或接触力阈值。

源码事实：当前 Go2 rough 的 `base_height_l2` 对扫描器所有有限命中点的世界 Z 求均值作为参考高度，再计算 `(z_base - mean_hit_z - target_height)^2`；它没有拟合平面或限定只取足端支撑点。全部未命中时该均值退回零，等价于未调整的世界高度目标。此回退只是既有行为，并未自动采用为 SWAP 要求。来源：项目 `rough_env_cfg.py:99-101`，Isaac Lab `source/isaaclab/isaaclab/envs/mdp/rewards.py:123-154`。

论文 Table III 给出高度误差公式和 Apollo 目标高度，但没有明确定义世界坐标、扫描平均面或足端支撑面，不能从符号 h 推出参考面。上述窗口、排除与腾空规则来自用户确认；窗口尺寸、点距、量程、可通行表面标记及接触检测细则仍需确认，未知数值继续保留 TBD。

### 已有来源可以解决的参数事实

- 论文 Table III 已给出指数尺度 `sigma=0.15`、`sigma_h=0.1`、`sigma_o=0.1`、air-time 减项 `0.5 s` 和 stumble 力倍率 `4`。它们有文献来源，不应作为无来源的新阈值询问用户。Go2 目标高度仍是独立适配项，不能直接采用论文 `0.6 m`。
